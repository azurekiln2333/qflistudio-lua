## Durable receipt and failure behavior

Each invocation creates a unique UTC/GUID directory under
`build/offline-ide-audit/build-receipts/`, retaining:

- `receipt.json`: requested Dart target/platform, SDK/core binding, product/core
  HEADs, primary failure and evidence errors, build/inspection outcomes, and
  referenced file paths, byte counts and full SHA256 digests.
- `source-before.json` and `source-after.json`: raw file hashes, binding metadata
  hashes and HEADs. The explicit target is hashed independently as well.
- Build and inspection command JSON with exact argument arrays, executable
  digests and working directory; their JSON digests are included in the receipt.
- The Flutter snapshot digest, retained build/inspection logs, inspection JSON,
  and final preserved HAP digest. Executable/snapshot/command records and the
  HAP are checked again before success is reported.

Fail on file-list/content, HEAD or binding drift. After capture still attempts
to hash the originally bound core when a changed SDK/package binding becomes
invalid, and records that invalid binding as unavailable. Missing/unreadable
source prevents successful evidence capture. Capture stability is checked on
both sides of each snapshot; snapshots are observations, not filesystem locks.

The existing exclusive `.build.lock` and caller `LogPath`/`ReportPath` options
are retained. Caller copies cannot overwrite source, SDK, binding files,
retained receipt directories, HAPs or signing-file extensions. Build failures
still attempt after/log/report capture. Evidence errors are accumulated;
nested cleanup restores Java options and cwd and disposes the lock even if
capture fails. The primary error is rethrown ahead of secondary evidence errors.
