# Lua 上架检查设计

## 边界与现状

行为缺口位于 Lua profile 的终端委托接线、核心离线 UI 门控，以及核心 Lua 内容数据；既有原生解释器、FFI、编辑器文件工具与核心 terminal backend 可复用。已有未提交修改作为被审查基线保留，禁止覆盖式回退。

根目录严格为 D:/MyNewProjects/qfli_lua。允许跨仓的唯一实施目标是 D:/MyNewProjects/qfli_studio_core 的共享策略与 Lua 专属内容。Herdr 3 个 pi 已验证 cwd，固定 pane 为 w9:p6、w9:p4、w9:p7，不能按 UI 焦点或相邻顺序猜 ID。

## 终端链路

在 Lua 仓新增 Lua 终端命令处理模块，挂到 luaProfile.terminalCommandDelegate；编辑器和独立页复用现有核心注入点与 SandboxShellBackend，不重复创建终端。

最少提供 lua/luac 帮助与版本、源代码/字节码运行、luac -p 源代码检查、luac -o 字节码生成；支持空格/Unicode 文件名、当前目录、模块与 input.txt，保留取消/超时/错误码。脚本参数不得被静默丢弃：若需扩展原生传参，采用新增函数/可选 Dart 参数并保留旧 C ABI。无法实现的上游 CLI 选项必须明确报错，禁止假成功。REPL/任意系统 shell 不在本次新增范围。

文本检查/编译沿用源代码语义，.luac 经运行路径验证；不把原本没有意义的字节码再编译动作当作缺陷。保留既有 JS/TS/sh 兼容运行。原生输出当前为运行结束后交付，不能在报告中夸称实时交互。

## 核心策略与文件责任

主代理集中集成核心共有生产文件：terminal/shell/sandbox_shell_backend.dart、services/code_import_service.dart。editor/editor_page.dart 与 pages/profile_page.dart 已发现核心并行任务 `10-15-offline-editor-gates` 正在修改，优先复用并验证其 offlineOnly 门控，不重复改写或代提交他人的补丁。若该任务未覆盖必要行为，先协调再补充。终端帮助/不支持提示泛化为宿主工具链。

导入服务非 Java 分支须执行既有文件名校验契约，不得先 trim 绕过空白拒绝。Java 专属名称规范化保持其当前契约。Windows 清理失败先确定资源寿命，再修正确切漏关闭/等待顺序，不用吞错或任意延时掩盖。

核心会话 pi wF:p2 因运行期间升级导致模块加载失败，未能完成协调；随后检测到核心任务 `10-15-offline-editor-gates` 及对应两个门控文件与测试变更。实施前重读核心 Git 状态；若他会话有重叠修改，先对照活文件与最新 HEAD，精确合并并重新测试，禁止覆盖或将他人变更混入本次提交。

## 内容数据与替换

采用 120 个递进主题（基础、函数/数据结构、进阶语言、工程实践各约 30），每主题包含独立说明、目标、前置知识、易错点、练习和实际体现主题的代码及确定性输出。教程与其配套示例可共享代码，但不同主题不得机械复用模板。所有内容离线可运行，所需输入和模块有显式夹具。

pi B 拥有 Lua 专属主题源、生成/验证工具与旧格式 assets/tutorials/lua.json。两份共享聚合 JSON 由主代理最终串行集成：读取最新文件，只替换 language == lua 条目，保存其余条目的规范化内容与顺序指纹，生成后再验证；检测并发写入时中止并重新读取。绝不删除整个核心 assets 或其他语言条目。

旧 Lua 数据只在新主题准备完成并通过预验证后替换，Git 提供按文件恢复点；符合用户仅重建本子项目数据的要求。聚合与兼容格式必须一致，runtime 元数据与实际引擎状态一致。

## 平台与证据

最终构建必须在 A、B、核心集成完成后执行，不能把历史 APK/HAP 当作本次验证。Flutter 使用既有 OHOS SDK 的 dart + flutter_tools.snapshot，Android/OHOS 分别用兼容 JBR，变量仅在进程内设置；共享 Flutter 启动锁导致相关命令串行调度。

分别检查 APK/HAP 原生 ABI、桥接导出、ArkTS 编译产物、Android 16KiB 对齐及签名状态，记录路径、大小、时间和 SHA256。OHPM 引用项目外 SDK 的生成路径本身是正常机制；仅修复实际损坏或构建失败。

使用 adb/hdc 现有连接尝试覆盖安装，不执行卸载/清数据。签名不匹配或授权被拒时保留应用数据并记录阻塞。设备安装成功后验证实际应用启动、离线菜单与双终端关键流程；不能用主机测试冒充设备测试。商店发行证书缺失不妨碍继续完成代码和可构建产物验证，但最终结论必须保留这一限制。
